# mimoCode-story 深度适配与潜力挖掘计划

## 项目现状

| 维度 | 现状 | 核心问题 |
|------|------|---------|
| 脚本 | 5 个 CommonJS 脚本，纯正则匹配 | 无 JSON 输出、无语义分析、无质量门禁 |
| 技能 | 14 个 skill，覆盖全流程 | 缺平台适配/简介生成/字数节奏工具 |
| 参考文档 | 60+ 共享参考 | 缺情绪曲线/角色声音一致性文档 |
| 质量体系 | 3 个脚本可选运行 | 无阻断式门禁，检查覆盖面不足 |
| 平台集成 | memory/task/actor 有浅层引用 | Goal/Dream/Max Mode/Voice/MCP 完全未用 |

## Phase 1：速赢（1-2 周）

### 1.1 脚本 JSON 输出 + 退出码规范化

**文件**: `skills/story-long-write/scripts/*.js`（5 个脚本）

所有脚本增加 `--json` 参数，输出结构化 JSON：
```json
{
  "status": "fail",
  "summary": { "errors": 2, "warnings": 5 },
  "issues": [
    { "type": "banned_word", "level": 1, "word": "不禁", "line": 42 }
  ]
}
```

- 复杂度: 低（每脚本约 30 行改动）
- 影响: 子智能体可结构化解析，为质量门禁打基础

### 1.2 consistency-check.js 扩展

**文件**: `skills/story-long-write/scripts/consistency-check.js`

当前问题：`consistency-check.js:82-108` 只检查物品和季节，完全跳过时间线和角色状态。

新增检查项：
- 时间线连续性（提取时间描述 vs `追踪/时间线.md`）
- 角色状态一致性（角色名+动作 vs `追踪/角色状态.md`）
- 已死角色复活检测
- 角色名拼写漂移检测（编辑距离算法）

- 复杂度: 中（约 150 行新增）
- 影响: 解决"角色状态追踪形同虚设"的问题

### 1.3 新脚本：quality-gate.js

**文件**: `skills/story-long-write/scripts/quality-gate.js`（新建）

串联所有检查脚本为统一入口：
```
node quality-gate.js <chapter-file> [project-dir]
  ├── style-lint（一级禁用词 > 0 → 阻断）
  ├── consistency-check（错误级 → 阻断）
  ├── foreshadow-check（逾期 > 50 章 → 警告）
  └── 字数检查（< 目标 90% → 阻断）
退出码：0=通过, 1=警告, 2=阻断
```

- 复杂度: 低（约 100 行）
- 影响: 将"建议检查"变为可执行的自动化阻断

### 1.4 AGENTS.md 门禁强制规则

**文件**: `AGENTS.md`

将"写完每章必须执行"第 7-9 步改为运行 `quality-gate.js`，退出码 2 时不得标记任务完成。

- 复杂度: 极低（约 10 行改动）
- 影响: 利用 MiMo Code 的 task 系统强制执行质量检查

### 1.5 新参考文档：emotion-curve-design.md

**文件**: `skills/_shared/references/emotion-curve-design.md`（新建）

覆盖：情绪曲线基本模型、按题材的情绪模板、章节级情绪标注方法、连续平坦检测与修复。

- 复杂度: 低（约 3000 字）
- 影响: 填补"情绪曲线无参考文档"的空白

## Phase 2：核心增强（3-6 周）

### 2.1 新脚本：voice-check.js（角色声音一致性）

**文件**: `skills/story-long-write/scripts/voice-check.js`（新建）

检查维度：语气词分布、句长分布、敬语/口语匹配、情绪词关联、口头禅一致性。
数据源：`追踪/角色状态.md` 性格锚点 + `设定/角色/*.md`

- 复杂度: 高（约 250 行，需建立角色声音基线）
- 影响: 解决"角色说话都一个味"的常见问题

### 2.2 新脚本：emotion-analyzer.js（情绪曲线分析）

**文件**: `skills/story-long-write/scripts/emotion-analyzer.js`（新建）

基于情绪关键词词典 + 强度权重，输出每章情绪热力图、峰值段落、平坦警告。

- 复杂度: 高（约 300 行，情绪词典需调优）
- 影响: 将主观"节奏感"变为可量化指标

### 2.3 新脚本：satisfaction-meter.js（爽点密度度量）

**文件**: `skills/story-long-write/scripts/satisfaction-meter.js`（新建）

指标：爽点间距、爽点密度（每 3000-5000 字 ≥1 个）、压制-释放比、最大爽点位置。

- 复杂度: 中（约 200 行）
- 影响: review skill 的"商业审查"从主观变客观

### 2.4 新技能：story-synopsis（简介/文案生成）

**文件**: `skills/story-synopsis/SKILL.md`（新建）

功能：按平台规范生成简介（起点 200-300 字、番茄 100-200 字、晋江 150-250 字），A/B 测试版生成 3 个版本供选择。

- 复杂度: 低（约 200 行 SKILL.md）
- 影响: 填补"写完书不会写简介"的常见需求

### 2.5 新技能：story-platform（平台适配）

**文件**: `skills/story-platform/SKILL.md`（新建）

功能：按平台规范格式化正文（字数、段落、引号风格、节奏），输出适配报告。

- 复杂度: 中（约 250 行 SKILL.md + 格式化脚本）
- 影响: 解决"写了书不知道怎么适配平台"的问题

### 2.6 新脚本：wordcount-pacer.js（字数节奏工具）

**文件**: `skills/story-long-write/scripts/wordcount-pacer.js`（新建）

根据细纲 + 目标字数，输出各段落字数分配指导（开篇钩子 10%、事件展开 40%、冲突升级 30%、爽点释放 13%、章尾钩子 7%）。

- 复杂度: 低（约 150 行）
- 影响: 写作前有明确字数分配，避免前松后紧

### 2.7 脚本 ESM 迁移

**文件**: 所有 `skills/*/scripts/*.js`

- `package.json` 添加 `"type": "module"`
- `require()` → `import`
- 统一 CLI 解析和输出格式

- 复杂度: 中（每脚本约 20 行改动）
- 影响: 代码现代化，为后续脚本定规范

### 2.8 新参考文档：character-voice-guide.md

**文件**: `skills/_shared/references/character-voice-guide.md`（新建）

覆盖：角色声音 5 维度、按身份/性格的声音模板、对话标签替代技巧、多角色对话声音区分。

- 复杂度: 低（约 4000 字）
- 影响: 为 voice-check.js 提供理论基础

## Phase 3：深度集成（6-12 周）

### 3.1 Goal 集成：自主写作模式

**文件**: `skills/story-long-write/SKILL.md`

在 SKILL.md 中增加 Goal 模式指引：
```
/goal 写到第30章，每章不低于3000字，一级禁用词为0
```
每章完成后自动运行 quality-gate.js，退出码 0 → 继续，2 → 阻断修复。

- 复杂度: 中（约 50 行新增）
- 影响: 实现"放手让 AI 写"的自主模式

### 3.2 Dream 集成：写作经验自动沉淀

**文件**: `skills/story-long-write/SKILL.md`

增加 Dream 指引，写作中发现的问题和解决方案自动存入 `MEMORY.md`。

- 复杂度: 低（约 30 行新增）
- 影响: 写作经验自动积累，不依赖人工记忆

### 3.3 Distill 集成：重复工作流自动发现

**文件**: `skills/story-long-write/SKILL.md`

增加 Distill 指引，自动发现"每章跑 3 脚本""每次读 10+ 文件"等重复模式并优化。

- 复杂度: 低（约 20 行指引）
- 影响: 自动发现可优化的工作流

### 3.4 子智能体并行写作

**文件**: `skills/story-long-write/SKILL.md`

启用并行写作模式：细纲就绪后 spawn 最多 5 个子智能体各写 1 章，主会话按顺序检查后写入。

- 复杂度: 高（约 80 行新增流程）
- 影响: 批量写作效率提升 3-5x

### 3.5 新技能：story-export（多格式导出）

**文件**: `skills/story-export/SKILL.md`（新建）

支持 TXT/EPUB/平台专用格式/校对稿导出。

- 复杂度: 中
- 影响: 写完后一键导出

### 3.6 新参考文档：pacing-mastery.md

**文件**: `skills/_shared/references/pacing-mastery.md`（新建）

覆盖：快慢节奏适用场景、段落/章节/卷级节奏控制、节奏与情绪关系、常见节奏问题修复。

- 复杂度: 低（约 4000 字）
- 影响: 节奏控制从经验变为可参考的方法论

## 质量体系升级总览

### 改进前
```
写正文 → 跑 3 个脚本（可选） → 人工判断 → 继续
```

### 改进后
```
写正文 → quality-gate.js（自动阻断）
  ├── style-lint（一级禁用词 = 0）
  ├── consistency-check（时间线+角色+物品+环境）
  ├── voice-check（角色声音一致性）      ← Phase 2
  ├── emotion-analyzer（情绪曲线不平坦）  ← Phase 2
  ├── satisfaction-meter（爽点密度）       ← Phase 2
  └── 字数检查（≥ 目标 90%）
  全部通过 → 继续
  任一阻断 → 修复后重跑
```

## 验证方案

### Phase 1 验证
1. 对 demo 项目 `让你管账号，你高燃混剪炸全网/` 运行 `quality-gate.js`
2. 确认退出码正确（有禁用词 → 2，有警告 → 1，全通过 → 0）
3. 确认 `--json` 输出可被 `JSON.parse()` 解析
4. 确认 AGENTS.md 门禁规则被 MiMo Code 读取并执行

### Phase 2 验证
1. 用 demo 章节运行 `voice-check.js`，确认角色声音基线建立
2. 用 demo 章节运行 `emotion-analyzer.js`，确认情绪曲线输出合理
3. 用 demo 章节运行 `satisfaction-meter.js`，确认爽点检测准确
4. 运行 `/story-synopsis` 确认简介生成符合平台规范

### Phase 3 验证
1. 用 `/goal` 设置写作目标，确认自主写作流程正确停止
2. 用 `/dream` 确认写作经验自动沉淀到 MEMORY.md
3. 用并行写作模式写 3 章，确认一致性检查通过
