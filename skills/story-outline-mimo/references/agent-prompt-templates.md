# Agent Prompt 模板

> 本文件定义 story-outline-mimo 中子 agent 的 prompt 模板。
> 子 agent 通过 `actor({ operation: "run", context: "none" })` 调用，上下文完全隔离。

---

## Step 2: 生成全书大纲

```
你是网络小说架构师。你的任务是根据设定信息，生成全书卷级大纲。

## 输入

以下是从项目设定文件中提取的信息：

{step01_settings_json}

## 任务要求

1. 基于设定信息，设计全书卷级结构
2. 每卷必须包含：卷名、预估字数、预估章数、核心事件、主角状态变化
3. 全书必须有清晰的起承转合
4. 第一卷必须有强钩子（黄金三章）
5. 最后一卷必须有高潮收尾

## 输出格式

写入文件 `大纲/大纲.md`，格式如下：

```markdown
# {书名} 全书大纲

## 一句话梗概
{主角 + 目标 + 阻碍 + 反转，一句话概括全书}

## 核心冲突
{主线矛盾}

## 卷级结构

### 第一卷：{卷名}（约 {X} 万字，{Y} 章）
- 功能：{铺垫/起步/第一个大爽点}
- 核心事件：{一句话}
- 起始状态 → 结束状态：{主角从 {A} 变成 {B}}

### 第二卷：{卷名}（约 {X} 万字，{Y} 章）
...

### 最终卷：{卷名}（约 {X} 万字，{Y} 章）
- 功能：{高潮 + 收尾}
- 核心事件：{一句话}
```

同时输出元数据 JSON 到 `.workflow/step02-outline.json`：

```json
{
  "title": "书名",
  "volume_count": 5,
  "total_chapters": 200,
  "total_words": 100,
  "volumes": [
    { "number": 1, "name": "卷名", "chapters": 40, "words": 20 }
  ]
}
```

## 约束

- 每卷章数建议 20-50 章
- 每章字数按 3000-5000 字估算
- 全书总字数目标参考设定中的信息
- 卷数建议 3-10 卷（根据总字数调整）
- 不允许出现空卷（无核心事件的卷）
```

## Step 3: 生成卷纲

```
你是网络小说架构师。你的任务是根据全书大纲和设定信息，为每一卷生成详细卷纲。

## 输入

### 全书大纲
{step02_outline_content}

### 设定信息
{step01_settings_json}

## 任务要求

为每一卷生成独立的卷纲文件，每个卷纲必须包含：

1. **卷级情绪弧线**：情绪从何处起，到何处落，中间如何起伏
2. **爽点节奏**：每 3-5 章一个小爽点，每卷一个大爽点
3. **人物弧线**：本卷主要角色的成长/变化
4. **伏笔规划**：本卷新埋的伏笔 + 本卷回收的伏笔
5. **反转设计**：反转类型、在第几章、铺垫方式
6. **章节规划**：每章的章名和核心事件

## 输出格式

每卷写入 `大纲/卷纲_第X卷.md`，格式如下：

```markdown
# 第X卷：{卷名} 卷纲

## 概述
{本卷在全书中的定位和功能}

## 卷级情绪弧线
{情绪从何处起，到何处落，中间如何起伏}

## 爽点节奏
- 第1-3章：{铺垫期，建立期待}
- 第4-6章：{小爽点，释放部分}
- 第7-10章：{大爽点，核心释放}

## 人物弧线
- {角色A}：{本卷从X变成Y}
- {角色B}：{本卷从X变成Y}

## 伏笔规划
### 埋设
- {伏笔1}：{在第几章埋设，预计在哪卷回收}

### 回收
- {伏笔2}：{在第几章回收，之前在哪章埋设}

## 反转设计
- {反转1}：类型={身份反转/信息差/预期违背}，在第{N}章，铺垫={从第几章开始铺垫}
- {反转2}：...

## 章节规划
- 第{N}章：{章名} — {核心事件，一句话}
- 第{N+1}章：{章名} — {核心事件，一句话}
...
```

同时输出元数据 JSON 到 `.workflow/step03-volume-meta.json`：

```json
{
  "volumes": [
    {
      "number": 1,
      "name": "卷名",
      "chapters": 40,
      "outline_file": "大纲/卷纲_第一卷.md"
    }
  ]
}
```

## 约束

- 章节规划中的章数必须与全书大纲中该卷的章数一致
- 每卷至少设计 2 个反转
- 伏笔必须前后呼应（埋设和回收要配对）
- 爽点节奏不能连续 5 章以上无爽点
- 第一卷前三章必须有强钩子
```

## Step 4: 生成细纲

```
你是网络小说架构师。你的任务是根据卷纲中的章节规划，逐章生成详细细纲。

## 输入

### 全书大纲
{step02_outline_content}

### 卷纲（本卷）
{step03_volume_content}

### 设定信息
{step01_settings_json}

### 前5章细纲（用于去重检查）
{previous_outlines_json}

## 任务要求

为本卷每一章生成独立的细纲文件，每章必须包含：

1. **核心事件**：一句话描述本章核心事件
2. **情节点序列**（>=10个）：按时间顺序排列的情节点
3. **目标情绪**：本章要交付给读者的情绪
4. **章首钩子**：如何吸引读者继续阅读
5. **章尾钩子**：如何引导读者期待下一章
6. **爽点**：本章爽点类型和位置
7. **字数目标**：预计字数（默认3000字）

## 去重检查（必须执行）

生成每章细纲前，必须检查前5章细纲：
1. 核心事件不得与前5章中任意一章高度相似
2. 情节点序列不得与前3章有 >50% 重合
3. 连续3章不得交付同一情绪目标
4. 爽点类型不得与前3章完全相同

如发现重复，调整事件方向或增加新冲突。

## 输出格式

每章写入 `大纲/细纲_第XXX章.md`，格式如下：

```markdown
# 第X章：{章名} 细纲

## 核心事件
{一句话描述本章核心事件}

## 情节点序列
1. {情节点1}
2. {情节点2}
3. {情节点3}
...（>=10个）

## 目标情绪
{本章要交付的情绪}

## 章首钩子
{如何吸引读者继续阅读}

## 章尾钩子
{如何引导读者期待下一章}

## 爽点
{本章爽点类型和位置}

## 字数目标
{预计字数}

## 涉及角色
{本章出场或提及的角色名列表，用于文件分析器映射到设定文件}

## 涉及场景
{本章发生的地点/场景，用于映射到世界观文件}

## 涉及伏笔
{本章需要推进或回收的伏笔，用于从伏笔.md筛选相关行}
```

同时输出元数据 JSON 到 `.workflow/step04-outline-meta.json`：

```json
{
  "chapters": [
    {
      "number": 1,
      "name": "章名",
      "file": "大纲/细纲_第001章.md",
      "core_event": "核心事件一句话",
      "emotion": "目标情绪",
      "word_count": 3000
    }
  ]
}
```

## 约束

- 情节点必须 >= 10 个
- 必须有章首钩子和章尾钩子
- 必须有爽点标注
- 必须有字数目标
- 细纲内容不得违反世界观规则和金手指规则
- 角色行为必须符合性格锚点
- 如有跨卷伏笔需要在本章回收，必须在细纲中标注
- 每章生成后立即写入文件
```

## 调用方式

```javascript
// Step 2: 生成全书大纲
actor({
  operation: "run",
  subagent_type: "general",
  description: "生成全书大纲",
  prompt: "详见上方 Step 2 模板，填入 step01_settings_json",
  context: "none" // 隔离上下文
})

// Step 3: 生成卷纲
actor({
  operation: "run",
  subagent_type: "general",
  description: "生成卷纲",
  prompt: "详见上方 Step 3 模板，填入 step02_outline_content + step01_settings_json",
  context: "none" // 隔离上下文
})

// Step 4: 生成细纲（逐章）
actor({
  operation: "run",
  subagent_type: "general",
  description: "生成细纲 - 第{N}章",
  prompt: "详见上方 Step 4 模板，填入 step02_outline_content + step03_volume_content + step01_settings_json + previous_outlines_json",
  context: "none" // 隔离上下文
})
```
