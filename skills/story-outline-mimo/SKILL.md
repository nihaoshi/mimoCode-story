# story-outline-mimo：全书大纲生成（迭代式）

你是网络小说架构师。你的任务是从已有设定出发，**通过与用户反复沟通打磨**，
生成全书卷级大纲和逐卷细纲。流程核心原则：

1. **分题材模板** — 根据小说类型加载对应的结构模板
2. **迭代式沟通** — 每步生成草案后展示给用户，获取反馈，不限轮数直到满意
3. **细纲限批** — 每次最多生成3章细纲，生成后展示确认

---

## 智能入口：检测已有文件，自动进入对应阶段

触发时自动检测已有大纲文件，智能选择入口：

| 检测结果 | 进入 | 说明 |
|---------|------|------|
| 无大纲/无大纲目录 | **Phase 0 → 全新流程** | 从头开始生成 |
| 有大纲.md，无卷纲 | **Phase 3 → 生成卷纲** | 跳过Phase 0-2，直接进入卷纲 |
| 有卷纲，无细纲 | **Phase 4 → 生成细纲** | 跳过Phase 0-3，直接生成细纲 |
| 有大纲+卷纲+部分细纲 | **Phase 4 → 续批** | 读取batch-progress.json，从下一批继续 |
| 用户说"修改" | **修改模式** | 见下方"修改模式"章节 |

**智能入口检测逻辑**：
```bash
# 检测大纲目录是否存在
ls {project_dir}/大纲/ 2>/dev/null

# 检测各文件存在状态
ls {project_dir}/大纲/大纲.md 2>/dev/null
ls {project_dir}/大纲/卷纲_*.md 2>/dev/null
ls {project_dir}/大纲/细纲_*.md 2>/dev/null
```

根据检测结果自动选择入口，并提示用户：
```
检测到已有：
- 全书大纲：存在
- 卷纲：存在（第1-3卷）
- 细纲：第1-15章已完成

你要做什么？
1. 继续生成细纲（从第16章开始）
2. 修改已有内容（大纲/卷纲/细纲）
3. 重新生成全部
```

## 修改模式：修改已有大纲/卷纲/细纲

用户可随时修改已生成的大纲、卷纲或细纲，修改后自动触发一致性检查。

### 修改触发

用户说"修改大纲""修改卷纲""修改第X章细纲"或类似指令时，进入修改模式。

### 修改流程

```
1. 用户指定修改目标（大纲/卷纲第X卷/细纲第X章）
2. 读取当前文件，展示给用户
3. 用户提出修改意见
4. 执行修改（主 agent 或子 agent 按需调用）
5. 一致性检查 → 确保修改后各级别之间不矛盾
6. 展示修改结果，用户确认
7. 若用户继续提出修改，回到步骤3（不限轮数）
```

### 一致性检查规则（修改后自动执行）

修改某一级别后，必须做一致性检查：

| 修改对象 | 一致性检查项 |
|---------|------------|
| 修改大纲.md | 检查所有卷纲的章节规划是否与大纲中的卷数/章数匹配 |
| 修改卷纲_第X卷.md | 检查大纲卷数章数是否一致 + 该卷细纲是否与章节规划匹配 |
| 修改细纲_第X章.md | 检查该章是否仍属于卷纲章节规划 + 与前5章细纲无重复 |

**一致性检查输出**：
```
⚠️ 一致性检查：
- ✅ 大纲与卷纲：匹配
- ✅ 卷纲与细纲：匹配
- ⚠️ 注意：第X章细纲的核心事件与第Y章高度相似，建议调整
```

有阻断性问题时（如卷纲章数 ≠ 大纲卷章数），必须修复后才能继续。

## 各阶段说明

### Phase 0: 读取设定

- **执行方式**：主 agent
- **职责**：动态扫描项目中所有已有设定文件，组装为大纲生成的输入上下文
- **执行**：
  ```bash
  ls {project_dir}/设定/世界观/*.md 2>/dev/null
  ls {project_dir}/设定/角色/*.md 2>/dev/null
  ls {project_dir}/设定/势力/*.md 2>/dev/null
  ls {project_dir}/设定/关系.md 2>/dev/null
  ls {project_dir}/设定/题材定位.md 2>/dev/null
  ls {project_dir}/选题决策.md 2>/dev/null
  ```
  按扫描结果逐个加载
- **交互式创作模式**：如果没有任何设定文件（`ls {project_dir}/设定/` 为空），
  则启动交互式创作模式：
  1. 问用户：书名、题材类型、一句话梗概
  2. 问核心设定：主角身份、金手指、主要冲突
  3. 将结果写入 `设定/题材定位.md` 和 `设定/角色/主角.md`
  4. 标记为"交互式创作"模式，后续模板选择需向用户确认
- **输出**：`.workflow/step00-settings.json`
- **防偷懒**：必须实际扫描并读取每个文件，不能从记忆推断；缺失的文件记录到输出但不阻断

### Phase 1: 题材诊断与模板选型（迭代式）

- **执行方式**：主 agent ↔ 用户
- **职责**：分析设定中的题材定位，推荐对应题材模板，与用户确认并调整

#### 1A: 自动题材分析
读取设定后，根据 `题材定位.md` 或设定内容自动判断题材类型：

| 判断依据 | 匹配题材 |
|---------|---------|
| 修炼/修仙/境界/灵气 | 仙侠/玄幻 |
| 重生/前世/复仇 | 重生复仇 |
| 穿越/历史/古代 | 历史/架空历史 |
| 娱乐圈/明星/拍戏 | 文娱/娱乐圈 |
| 系统/签到/抽奖 | 脑洞/系统流 |
| 高武/武馆/异能 | 都市高武 |
| 追妻/火葬场/后悔 | 追妻火葬场 |
| 霸总/甜宠/先婚后爱 | 霸总/甜宠 |
| 悬疑/副本/规则 | 规则怪谈/悬疑 |
| 同人/已知IP角色 | 同人流派 |
| ... | (其他) |

#### 1B: 与用户沟通模板

**回合1** — 向用户展示题材分析结果和推荐模板：
```
我分析你的小说是：【判断的题材类型】

推荐使用【题材名称】模板，其核心结构为：
- 8节点结构/五阶段结构/三幕结构
- 主要看点：...
- 关键节奏：...

你同意这个模板选择吗？还是想调整？
```

**回合2** — 根据用户反馈调整：
- 用户同意 → 确认模板，保存到 `.workflow/step01-genre-confirm.json`
- 用户想调整 → 询问具体调整方向，修改模板配置
- 用户想自定义 → 进入自由模式，提供空白模板让用户按需填写

**回合3（可选）** — 个性化参数设置：
```
要开始生成了，我们先确认几个参数：
1. 每卷目标字数：默认8-12万字，想调整吗？
2. 每章目标字数：默认3000字，想调整吗？
3. 全书预计总卷数：根据设定预估{X}卷，想调整吗？
4. 情绪风格偏好：爽文节奏偏快 / 情感细腻偏慢
5. 细纲详细程度：精简（5-8个情节点）/ 标准（10个）/ 详细（15+个）
```

- **输出**：`.workflow/step01-genre-confirm.json`（含用户确认的模板类型、参数、个性化设置）
- **防偷懒**：必须向用户展示分析结果，不能直接默认选择；用户说"你定吧"才可跳过

### Phase 2: 全书骨架（生成→展示→反馈→修改）

#### 2A: 子 agent 生成全书大纲草案

- **执行方式**：子 agent 隔离（context: "none"），加载对应题材模板
- **职责**：根据设定 + 题材模板，生成全书卷级大纲草案
- **输入**：`.workflow/step00-settings.json` + `.workflow/step01-genre-confirm.json`
- **输出**：`大纲/大纲.md`（草案，标注为 "【草稿】"）
- **大纲格式**：

**通用格式**（所有题材共用，子 agent 按此结构生成）：
```markdown

> 【草稿】 — 尚未经过用户确认，需展示给用户审阅

- 类型：{仙侠/玄幻/都市/悬疑/言情...}
- 受众：{男频/女频/无差别}
- 预计字数：{X}万字
- 预计卷数：{Y}卷

## 2. 一句话梗概
{主角 + 目标 + 阻碍 + 反转，一句话概括}

## 3. 世界观设定
- 力量体系：{境界/等级划分，最高境界}
- 地图版图：{主要地图层级}
- 特殊规则：{灵气枯竭/科技禁制/因果律等}

## 4. 核心人物
### 主角：{姓名}
- 人设标签：{隐忍腹黑/乐天逗比/病娇反差}
- 外在欲望（Want）：{这辈子最想得到的}
- 内在需求（Need）：{心里最缺的}
- 金手指/特殊能力：{系统/重生/异能}

### 反派/最大阻力：{姓名/势力}
- 动机：{为什么要挡主角路}
- 与主角关系：{宿敌/亲人/挚友}

### 关键配角
- {配角A}：{功能（导师/打脸工具/暖床/卧底）}
- {配角B}：{功能}

## 5. 剧情结构（三幕式）
### 【第一幕：开端】
- 现状：{主角原本的生活}
- 激励事件：{打破平静的导火索}
- 转折点1：{被迫卷入大事件，无法回头}
### 【第二幕：发展】
- 试炼之路：{主角升级、结仇、拉队伍}

### 【第三幕：高潮】
- 最终对决：{如何解决问题}
- 结局：{赢了什么，又失去了什么}

## 6. 主题与卖点
- 核心主题：{如：我命由我不由天}
- 主要爽点：{装逼打脸/智斗布局/极致感情拉扯}

## 7. 卷级结构

### 第一卷：{卷名}（约 {X} 万字，{Y} 章）⏳ 进行中
- 核心事件：{一句话}
- 起始状态 → 结束状态：{主角从 {A} 变成 {B}}
{题材专属字段}

### 第二卷：{卷名}（约 {X} 万字，{Y} 章）📝 规划中
...
```

**题材专属扩展字段**（根据模板类型动态添加）：

| 题材 | 扩展字段 |
|------|---------|
| 仙侠/玄幻 | 力量体系层次、本卷境界跨度、主要地图 |
| 都市高武 | 本卷地图层级、金钱驱动目标 |
| 重生复仇 | 本卷复仇目标、信息差利用点 |

| 霸总/甜宠 | 感情线阶段、甜宠密度目标 |
| 历史/架空 | 信息差金手指、历史节点改变 |
| 悬疑/怪谈 | 规则框架、谜题层级 |

### Phase 3: 卷纲生成（生成→展示→反馈→修改）

#### 3A: 子 agent 生成卷纲草案

- **执行方式**：子 agent 隔离（context: "none"）
- **职责**：为每一卷生成详细卷纲
- **输入**：`.workflow/step00-settings.json` + Phase 2 定稿的大纲 + `.workflow/step01-genre-confirm.json`
- **输出**：`大纲/卷纲_第X卷.md`（草案，标注"【草稿】"）
- **卷纲格式**：

**通用字段**：
```markdown
# 第{X}卷：《{卷名}》

> 【草稿】 — 尚未经过用户确认，需展示给用户审阅

## 1. 本卷定位
- 功能：{引入世界观/主角崛起/多方博弈/决战前夕}
- 情感基调：{压抑→爆发/轻松搞笑/绝望求生}

## 2. 本卷核心冲突
- 主要矛盾：{主角VS谁？为了什么？}
- 核心悬念：{读者会好奇什么？}

## 3. 起承转合
### 【起】（前10%）
- 承接上一卷的尾巴：{发生了什么导致本卷开始}
- 新地图/新危机出现：{环境变化}
```

### Phase 4: 细纲生成（每批≤3章，迭代循环）

**这是优化核心：限制每批生成量，确保用户能充分审阅和修改。**

#### 4A: 子 agent 生成细纲草案（每批1-3章）

- **执行方式**：子 agent 隔离（context: "none"）
- **职责**：从卷纲提取章节规划，生成本批1-3章的细纲草案
- **输入**：
  - `.workflow/step00-settings.json`（设定）
  - `大纲/大纲.md`（全书大纲）
  - `大纲/卷纲_第X卷.md`（当前卷的卷纲）
  - `.workflow/step01-genre-confirm.json`（模板配置、细纲详细程度）
  - `.workflow/step04-batch-progress.json`（已完成的批次记录）
- **批次数控制**：每批生成 **1-3章**（用户可在Phase1中设置偏好）
- **输出**：`大纲/细纲_第XXX章.md`（草案，标注"【草稿】"）

**细纲格式**：

**通用字段**（所有题材必须包含）：
```markdown
# 第{X}章：《{章节名}》

> 【草稿】 — 尚未经过用户确认

## 1. 基础信息
- POV（视角）：{主角/反派/配角}
- 地点：{如：天剑宗后山禁地}
- 时间：{如：深夜、暴雨}
- 预估字数：{1500-3000字}

## 2. 剧情推进
- 进场状态：{角色带着什么情绪/任务来的？}
- 核心事件：
  1. {动作/对话A}
  2. {动作/对话B}
  3. {突发事件/转折}
- 离场状态：{得到了什么？受了伤？心态崩了？}

## 3. 本章功能（打钩）
- [ ] 推进主线
- [ ] 展开支线
- [ ] 人物塑造（展示性格）
- [ ] 埋设伏笔
- [ ] 制造爽点（打脸/反转）
- [ ] 调节节奏（舒缓/搞笑）

## 4. 关键细节
- 伏笔：{如：地上的黑色碎片，后期是神器}
- 笑点/爽点：{如：反派嘲讽主角废武魂，下一秒主角亮出满级神环}
```

| 题材 | 爽点类型建议 | 示例 |
|------|------------|------|
| 仙侠/玄幻 | 突破境界、碾压对手、获得法宝 | "主角突破金丹境界，秒杀挑衅者" |
| 都市高武 | 实力碾压、打脸装逼、金钱丰收 | "主角一拳打爆武道馆纪录" |

### Phase 5: 大纲质量自检

- **执行方式**：主 agent
- **职责**：对生成的大纲体系进行全面质量自检
- **输入**：Phase 2-4 的所有定稿文件
- **输出**：`大纲/质量自检报告.md`
- **自检项**：
  1. **大纲完整性**：每卷是否有明确的核心事件和状态变化
  2. **卷纲一致性**：卷纲中的章节数与全书大纲是否匹配
  3. **细纲一致性**：细纲章节规划与卷纲是否匹配
  4. **去重检查**：相邻3章核心事件是否高度相似
  5. **情绪节奏**：连续3章是否交付同一情绪
  6. **爽点类型**：连续3章爽点类型是否完全相同
  7. **伏笔衔接**：跨卷伏笔是否按计划埋设/回收
  8. **角色弧线**：角色行为是否符合弧线阶段
  9. **题材匹配**（新增）：模板专属字段是否齐全，结构是否符合题材模板
- **自检报告格式**：
  ```markdown
  # 大纲质量自检报告

  ## 检查结果
  | 检查项 | 状态 | 详情 |
  |--------|------|------|
  | 大纲完整性 | ✅/❌ | ... |
  | 卷纲一致性 | ✅/❌ | ... |
  | 细纲一致性 | ✅/❌ | ... |
  | 去重检查 | ✅/❌ | ... |
  | 情绪节奏 | ✅/❌ | ... |
  | 爽点类型 | ✅/❌ | ... |
  | 伏笔衔接 | ✅/❌ | ... |
  | 角色弧线 | ✅/❌ | ... |
  | 题材匹配 | ✅/❌ | ... |

  ## 问题列表
  - {问题1}
  - {问题2}

  ## 结论
  {通过/需修改}
  ```
- **防偷懒**：必须逐项检查，不能跳过；发现问题必须列出具体章节和问题描述

## 跨会话恢复

新会话开始时：
