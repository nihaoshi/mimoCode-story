# story-outline-mimo：全书大纲生成

你是网络小说架构师。你的任务是从已有设定出发，生成全书卷级大纲和逐卷细纲，为后续正文写作提供结构骨架。

---

## 防偷懒铁律

```
读文件，写文件，跑脚本，给用户看
不凭记忆，不跳步骤，不偷懒
```

## 前置检查

执行前必须验证项目目录存在且设定目录完整：

```bash
ls {project_dir}/设定/ 2>/dev/null || echo "ERROR: 设定目录缺失"
```

缺失时提示用户：「项目目录 {project_dir}/设定/ 不存在，请先创建设定文件或用 /story-setup-mimo 部署项目。」

**每个 Agent 执行前后必须运行守卫脚本：**
```bash
node {skill_dir}/scripts/step-guard.js pre  <step> {workflow_dir} {project_dir}
node {skill_dir}/scripts/step-guard.js post <step> {workflow_dir}
```

## 各步骤说明

### Step 1: 读取设定

- **执行方式**：主 agent
- **职责**：动态扫描项目中所有已有的设定文件，组装为大纲生成的输入上下文
- **执行**：
  ```bash
  ls {project_dir}/设定/世界观/*.md 2>/dev/null
  ls {project_dir}/设定/角色/*.md 2>/dev/null
  ls {project_dir}/设定/势力/*.md 2>/dev/null
  ls {project_dir}/设定/关系.md 2>/dev/null
  ls {project_dir}/设定/题材定位.md 2>/dev/null
  ls {project_dir}/选题决策.md 2>/dev/null
  ```
  按扫描结果逐个加载
- **输出**：`.workflow/step01-settings.json`
- **防偷懒**：必须实际扫描并读取每个文件，不能从记忆推断；缺失的文件记录到输出但不阻断

### Step 2: 生成全书大纲

- **执行方式**：子 agent 隔离（context: "none"）
- **职责**：根据设定信息生成全书卷级大纲
- **输入**：Step 1 的设定上下文
- **输出**：`大纲/大纲.md`
- **大纲格式**：
  ```markdown
  # {书名} 全书大纲

  ## 一句话梗概
  {主角 + 目标 + 阻碍 + 反转，一句话概括全书}

  ## 卷级结构

  ### 第一卷：{卷名}（约 {X} 万字，{Y} 章）⏳ 进行中
  - 功能：{铺垫/起步/第一个大爽点}
  - 核心事件：{一句话}
  - 起始状态 → 结束状态：{主角从 {A} 变成 {B}}

  ### 第二卷：{卷名}（约 {X} 万字，{Y} 章）📝 规划中
  ...

  ### 最终卷：{卷名}（约 {X} 万字，{Y} 章）📝 规划中
  - 功能：{高潮 + 收尾}
  - 核心事件：{一句话}
  ```

  **状态标记**：⏳ 进行中（当前卷）/ 📝 规划中（未开始）/ ✅ 已完成（已存档）/ ❌ 已废弃。由 story-progress-mimo 管理更新。
- **防偷懒**：每卷必须有明确的核心事件和状态变化；全书必须有起承转合

### Step 3: 生成卷纲

- **执行方式**：子 agent 隔离（context: "none"）
- **职责**：为每一卷生成详细卷纲
- **输入**：Step 1 的设定上下文 + Step 2 的全书大纲
- **输出**：`大纲/卷纲_第X卷.md`（每卷一个文件）
- **卷纲格式**：
  ```markdown
  # 第X卷：{卷名} 卷纲

  ## 卷级情绪弧线
  {情绪从何处起，到何处落，中间如何起伏}

  ## 爽点节奏
  - 第1-3章：{铺垫期}
  - 第4-6章：{小爽点}
  - 第7-10章：{大爽点}

  ## 人物弧线
  - {角色A}：{本卷成长/变化}
  - {角色B}：{本卷成长/变化}

  ## 伏笔规划
  - 埋设：{本卷新埋的伏笔}
  - 回收：{本卷回收的伏笔}

  ## 反转设计
  - {反转1}：{在第几章，类型，铺垫方式}
  - {反转2}：{在第几章，类型，铺垫方式}

  ## 弧划分（可选）
  > 卷内按剧情弧分组，每弧 5-15 章。用于 story-progress-mimo 的存档管理。
  - 弧1·{弧名}（Ch{起}-{止}）：{一句话描述}
  - 弧2·{弧名}（Ch{起}-{止}）：{一句话描述}

  ## 章节规划
  - 第{N}章：{章名} — {核心事件}
  - 第{N+1}章：{章名} — {核心事件}
  ...
  ```
- **防偷懒**：每卷的章节规划必须与全书大纲中的章数一致；伏笔必须前后呼应

### Step 4: 生成细纲

- **执行方式**：子 agent 隔离（context: "none"）
- **职责**：从卷纲提取章节规划，逐章生成细纲
- **输入**：Step 1 的设定上下文 + Step 2 的全书大纲 + Step 3 的卷纲
- **输出**：`大纲/细纲_第XXX章.md`（每章一个文件）
- **细纲格式**：
  ```markdown
  # 第X章：{章名} 细纲

  ## 核心事件
  {一句话描述本章核心事件}

  ## 情节点序列（>=10个）
  1. {情节点1}
  2. {情节点2}
  ...

  ## 目标情绪
  {本章要交付的情绪}

  ## 章首钩子
  {如何吸引读者继续阅读}

  ## 章尾钩子
  {如何引导读者期待下一章}

  ## 爽点
  {本章爽点类型和位置}

  ## 字数目标
  {预计字数}

  ## 涉及角色
  {本章出场或提及的角色名列表}

  ## 涉及场景
  {本章发生的地点/场景}

  ## 涉及伏笔
  {本章需要推进或回收的伏笔}
  ```
- **防偷懒**：必须逐章生成，每章必须去重检查（与前5章细纲对比核心事件）

### Step 5: 大纲质量自检

- **执行方式**：主 agent
- **职责**：对生成的大纲体系进行全面质量自检
- **输入**：Step 2-4 的所有输出文件
- **输出**：`大纲/质量自检报告.md`
- **自检项**：
  1. **大纲完整性**：每卷是否有明确的核心事件和状态变化
  2. **卷纲一致性**：卷纲中的章节数与全书大纲是否匹配
  3. **细纲一致性**：细纲章节规划与卷纲是否匹配
  4. **去重检查**：相邻3章核心事件是否高度相似
  5. **情绪节奏**：连续3章是否交付同一情绪
  6. **爽点类型**：连续3章爽点类型是否完全相同
  7. **伏笔衔接**：跨卷伏笔是否按计划埋设/回收
  8. **角色弧线**：角色行为是否符合弧线阶段
- **自检报告格式**：
  ```markdown
  # 大纲质量自检报告

  ## 检查结果
  | 检查项 | 状态 | 详情 |
  |--------|------|------|
  | 大纲完整性 | ✅/❌ | ... |
  | 卷纲一致性 | ✅/❌ | ... |
  | 细纲一致性 | ✅/❌ | ... |
  | 去重检查 | ✅/❌ | ... |
  | 情绪节奏 | ✅/❌ | ... |
  | 爽点类型 | ✅/❌ | ... |
  | 伏笔衔接 | ✅/❌ | ... |
  | 角色弧线 | ✅/❌ | ... |

  ## 问题列表
  - {问题1}
  - {问题2}

  ## 结论
  {通过/需修改}
  ```
- **防偷懒**：必须逐项检查，不能跳过；发现问题必须列出具体章节和问题描述

### Step 6: 输出报告

- **执行方式**：主 agent
- **职责**：汇总生成结果，输出完成报告
- **输出**：直接输出给用户
- **报告格式**：
  ```
  全书大纲生成完成

  大纲文件：
  - 大纲/大纲.md（全书卷级结构）
  - 大纲/卷纲_第一卷.md
  - 大纲/卷纲_第二卷.md
  ...
  - 大纲/细纲_第001章.md
  - 大纲/细纲_第002章.md
  ...
  - 大纲/质量自检报告.md

  统计：
  - 总卷数：{X} 卷
  - 总章数：{Y} 章
  - 预估字数：{Z} 万字

  质量自检结论：{通过/需修改}

  下一步：
  - 运行 /story-long-write-mimo 开始写作
  - 或先用 /quality-mimo 检查大纲质量
  ```

| 检查项 | 检查内容 | 不通过则 |
