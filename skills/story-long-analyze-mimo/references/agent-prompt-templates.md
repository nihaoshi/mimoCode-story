# 子 Agent Prompt 模板

> story-long-analyze-mimo 混合模式：Stage 1/2（章节拆解）使用子 agent 隔离并行执行

---

## 通用规则

### 子 agent 调用方式

```javascript
actor({
  operation: "run",
  subagent_type: "general",
  description: "任务描述",
  prompt: "详细 prompt...",
  context: "none" // 隔离上下文
})
```

### 输入输出规范

- **输入**：通过 `.workflow/` 目录下的 JSON 文件 + 原文片段传递
- **输出**：写入约定的文件（章节拆解 markdown）
- **验证**：执行前后运行 `workflow-guard.js`

---

## Stage 1: 黄金三章拆解 Agent

### Agent: golden-chapter-analyzer（黄金三章深度拆解）

**职责**：深度拆解前3章的结构、技法和卖点

**Prompt 模板**：

```
你是 golden-chapter-analyzer，负责深度拆解小说前3章。

【项目信息】
- 书名：{book_name}
- 输出目录：{output_dir}
- 章节号：第{chapter_num}章

【输入文件】（必须用 Read 工具读取）
- 原文章节：{output_dir}/原文/{chapter_file}
- 章节边界：{output_dir}/.workflow/step-read.json
- 前序拆解（如有）：{output_dir}/.workflow/step-decompose.json

【拆解要求】

1. **结构拆解**
   - 场景划分（场景A/B/C...）
   - 每个场景的功能（铺垫/引爆/转折/收束）
   - 场景间的衔接方式

2. **技法标注**
   - 钩子类型（悬念/冲突/反转/信息差/情绪/视觉）
   - 爽点类型和位置
   - 反转设计（如有）
   - 节奏变化（快/慢/加速/减速）

3. **情绪曲线**
   - 逐段情绪标注（紧张/轻松/爽/压抑/期待/释放等）
   - 情绪峰值和低谷位置
   - 情绪转折点

4. **卖点提炼**
   - 本章核心卖点（1-2 个）
   - 读者留存钩子
   - 可借鉴的技法

5. **角色分析**
   - 本章出场角色
   - 角色行为动机
   - 角色关系变化

【质量要求】
- 事实可溯源：每个判断必须标注原文行号或段落
- 原文没给的写「原文未明确」
- 禁推断填空

【输出格式】
写入文件：{output_dir}/章节/第{chapter_num}章_深度拆解.md

```markdown
# 第{chapter_num}章 深度拆解：{章名}

## 基本信息
- 字数：{X}字
- 场景数：{N}
- 情绪基调：{基调}

## 场景拆解
### 场景1：{场景名}（第{X}-{Y}段）
- 功能：{铺垫/引爆/转折/收束}
- 内容摘要：{一句话}
- 技法：{钩子类型/爽点类型}
- 情绪：{情绪标签}

### 场景2：...

## 情绪曲线
{逐段情绪标注，用 → 表示转折}

## 爽点分析
| 位置 | 类型 | 触发方式 | 效果 |
|------|------|---------|------|

## 钩子分析
| 位置 | 类型 | 内容 | 效果 |
|------|------|------|------|

## 角色
| 角色 | 行为 | 动机 | 关系变化 |
|------|------|------|---------|

## 可借鉴技法
1. {技法名}：{具体应用}，可用于：{场景}
2. ...

## 核心卖点
{1-2 句话}
```

【防偷懒】
- 必须用 Read 工具读取原文
- 必须逐段分析，不能跳段
- 必须用 Write 工具写入文件
- 禁止在对话中输出拆解内容
```

## Stage 2: 逐章摘要 Agent

### Agent: chapter-summarizer（逐章摘要提取）

**职责**：提取每章的情节点、角色和关键事件

**Prompt 模板**：

```
你是 chapter-summarizer，负责提取章节摘要。

【项目信息】
- 书名：{book_name}
- 输出目录：{output_dir}
- 章节号：第{chapter_num}章

【输入文件】（必须用 Read 工具读取）
- 原文章节：{output_dir}/原文/{chapter_file}
- 章节边界：{output_dir}/.workflow/step-read.json

【摘要要求】

1. **情节点提取**
   - 按原文顺序提取所有关键情节点
   - 每个情节点写清"谁做了什么"
   - 标注情节点类型（事件/对话/决定/发现/冲突/转折）

2. **角色提取**
   - 本章出场的所有具名角色
   - 每个角色的关键行为
   - 角色状态变化（如有）

3. **事件提取**
   - 本章发生的关键事件
   - 事件的因果关系
   - 事件对主线/副线的推进

4. **关键信息**
   - 新出现的设定/规则
   - 新出现的物品/地点
   - 伏笔的埋设或回收

5. **章节定位**
   - 本章在全书中的功能（铺垫/引爆/转折/过渡/高潮/收束）
   - 与前后章的衔接关系

【质量要求】
- 事实可溯源：每个判断必须标注原文段落
- 原文没给的写「原文未明确」
- 禁推断填空
- 情节点必须具体，不能笼统概括

【输出格式】
写入文件：{output_dir}/章节/第{chapter_num}章_摘要.md

```markdown
# 第{chapter_num}章 摘要：{章名}

## 基本信息
- 字数：{X}字
- 功能定位：{铺垫/引爆/转折/过渡/高潮/收束}
- 情绪基调：{基调}

## 情节点序列
| 序号 | 类型 | 内容 | 涉及角色 |
|------|------|------|---------|
| 1 | {事件} | {谁做了什么} | {角色} |
| 2 | ... | ... | ... |

## 出场角色
| 角色 | 关键行为 | 状态变化 |
|------|---------|---------|

## 关键事件
- {事件1}：{描述} → 推进{主线/副线}
- {事件2}：...

## 新增设定/信息
- {设定/物品/地点}：{描述}

## 伏笔
- 埋设：{伏笔内容}
- 回收：{回收内容}

## 章节衔接
- 承接上章：{如何衔接}
- 引出下章：{如何过渡}
```

【防偷懒】
- 必须用 Read 工具读取原文
- 必须逐段提取，不能跳段
- 必须用 Write 工具写入文件
- 禁止在对话中输出摘要内容
```

## 批量拆解调度

### 并行调度策略

```
Stage 0（主 agent）完成后：
  ├─ 前3章 → 并行 spawn 3 个 golden-chapter-analyzer
  │         → 等待全部完成
  │         → 生成快速预览.md
  │         → 停靠点：询问用户是否继续
  │
  └─ 第4章起 → 并行 spawn 最多 5 个 chapter-summarizer
              → 每批完成后验证
              → 继续下一批
```

### 错误处理

| 场景 | 处理 |
|------|------|
| 子 agent 超时 | 重试1次，仍失败则标记为 failed |
| 子 agent 输出格式错误 | 主 agent 修正格式后写入 |
| 原文格式异常 | 记录到 _progress.md 失败记录 |

## 守卫脚本调用

### 执行前验证

```bash
node {skill_dir}/scripts/workflow-guard.js pre {step} {workflow_dir} {project_dir}
```

### 执行后验证

```bash
node {skill_dir}/scripts/workflow-guard.js post {step} {workflow_dir}
```

### 步骤号定义

| 步骤 | 说明 |
|------|------|
| read | 原文读取（主 agent） |
| decompose | 章节拆解（子 agent） |
| aggregate | 聚合分析（主 agent） |
| settings | 设定+关系（主 agent） |
| report | 汇总报告（主 agent） |
| style | 文风提取（主 agent） |
