# 同章内流水线并行

> 版本：1.0.0
> 更新时间：2026-06-12
> 目标：单章耗时降低30-40%

---

## 概述

将单章写作流程拆分为**准备阶段**（只读）和**写作阶段**（读+写），利用MiMo Code的Actor系统实现流水线并行。

---

## 流水线架构

```
┌─────────────────────────────────────────────────────────────┐
│                    单章写作流水线                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐     │
│  │  准备阶段   │───▶│  写作阶段   │───▶│  检查阶段   │     │
│  │  (只读)     │    │  (读+写)    │    │  (只读)     │     │
│  └─────────────┘    └─────────────┘    └─────────────┘     │
│       │                  │                  │               │
│       ▼                  ▼                  ▼               │
│  story-explorer    narrative-writer    consistency-checker  │
│       │                  │                  │               │
│       ▼                  ▼                  ▼               │
│  准备层输出          正文输出            质量报告            │
│  - 最简记忆包       - 正文.md           - 一致性检查        │
│  - 文风召回结果                         - 禁用词扫描        │
│  - 模块召回结果                         - 钩子检查          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**输入**：

---

### 阶段2：写作阶段（读+写）

**执行者**：narrative-writer 子智能体（通过 MiMo Code 的 actor 工具 spawn，或主会话降级执行）

**输入**：
- 准备阶段输出（JSON）
- 上一章正文

**输出**：
- 正文/第{N}章_{章名}.md

**耗时预估**：60-120秒

---

### 阶段3：检查阶段（只读）

**执行者**：consistency-checker 子智能体（通过 MiMo Code 的 actor 工具 spawn，或主会话降级执行）

**输入**：
- 本章正文
- 追踪文件

**输出**：
- 质量报告（一致性检查+禁用词扫描+钩子检查）

**耗时预估**：15-30秒

## 并行优化

### 1. 跨章预准备

在写第N章时，可以预加载第N+1章的准备阶段数据：

```
时间线：
T0: 开始写第N章（准备阶段）
T1: 第N章准备完成，开始写第N章（写作阶段）
T2: 同时开始第N+1章准备阶段（预加载）
T3: 第N章写作完成
T4: 第N+1章准备已完成，直接开始写作阶段
```

**实现方式**：
- 在第N章写作阶段开始时，spawn一个轻量actor预加载第N+1章
- 第N章完成后，第N+1章的准备数据已就绪

### 2. 批量细纲生成

卷纲确认后，可以并行生成10章细纲：

```
时间线：
T0: 主会话确认卷纲
T1: spawn 10个actor并行生成细纲
T2: 所有细纲生成完成
T3: 主会话统一审核
```

**实现方式**：
- 每个actor负责1章细纲
- 细纲之间相互独立（除了章节顺序）
- 主会话审核后锁定

### 3. 检查阶段并行

如果项目有多个检查器，可以并行执行：

```
时间线：
T0: 写作完成
T1: 同时启动3个检查器
    - consistency-checker（一致性）
    - anti-ai-checker（去AI味）
    - quality-checker（质量）
T2: 所有检查完成
T3: 汇总报告
```

## Actor调用模板

### story-explorer（准备阶段）

```
Actor(subagent_type: "explore", prompt: "项目目录：{dir}\n查询类型：chapter_prepare\n查询参数：准备写第 {N} 章\n细纲文件：大纲/细纲_第{N}章.md")
```

### narrative-writer（写作阶段）

```
Actor(subagent_type: "general", prompt: "项目目录：{dir}\n任务描述：写正文\n章节：第{N}章\n准备层输出：{准备阶段JSON}\n上一章：正文/第{N-1}章_*.md")
```

### consistency-checker（检查阶段）

```
Actor(subagent_type: "general", prompt: "项目目录：{dir}\n任务描述：一致性检查\n检查范围：第{N}章\n检查类型：事实冲突+伏笔断线+角色属性不一致")
```

## 降级策略

当actor不可用时，降级到主会话串行执行：

1. **story-explorer不可用** → 主会话手动加载上下文
2. **narrative-writer不可用** → 主会话直接写作
3. **consistency-checker不可用** → 主会话手动检查

降级时保持原有串行流程，不阻塞写作。
