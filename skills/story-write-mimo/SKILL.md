# story-write-mimo — 统一写作入口

> 版本：1.0.0
> 整合自 story-long-write-mimo / story-chapter-write-mimo / story-chapter-fast-write-mimo / story-chapter-ultra-write-mimo

---

## 模式选择

| 模式 | 触发词 | 特点 | 适用场景 |
|------|--------|------|---------|
| **standard** | 默认 | 完整流程，2轮修复，BLOCK+WARN全检测 | 常规写作 |
| **fast** | `fast`、`快速` | 最简记忆包+1轮修复，只检测BLOCK项 | 快速迭代 |
| **ultra** | `极致`、`深度` | 全量检测+深度检测，3轮评分修复 | 精品打磨 |
| **batch** | `batch`、`批量` | 一次写2-3章，自适应批量 | 日更批量 |
| **revise** | `revise`、`修改`、`重写`、`回炉` | 加载前后章上下文+备份+级联检查 | 修改重写 |

用户输入示例：
- `/story-write-mimo` → standard模式
- `/story-write-mimo fast` → fast模式
- `/story-write-mimo 极致写章` → ultra模式
- `/story-write-mimo 续写下一章` → standard模式，续写
- `/story-write-mimo 重写第5章` → revise模式
- `/story-write-mimo batch` → batch模式，批量写作

### 模式差异详解

#### standard模式
- Step 01-09: 完整执行
- Step 05: 执行全部5项脚本检测（4 BLOCK + 1 WARN）
- Step 06: 执行全部5项LLM分析检测（2 BLOCK + 3 WARN）
- Step 07-08: 修复循环上限2轮
- Step 08.5-08.6: 百分制评分+评分修复
- 上下文读取：分层按需读取（Layer 1-3）

#### fast模式
- Step 01-09: 完整执行
- **最简记忆包**：只加载最少上下文（细纲+涉及角色状态+最近1章摘要）
- Step 05: 只执行4项BLOCK脚本检测（跳过跨章节WARN）
- Step 06: 只执行2项BLOCK LLM检测（跳过3项WARN）
- Step 07-08: 修复循环上限1轮
- Step 08.5-08.6: 百分制评分+评分修复
- 上下文读取：只读细纲涉及的2-3个文件

#### ultra模式
- Step 01-09: 完整执行
- Step 05: 执行全部5项脚本检测 + **全量一致性审计**（full-consistency-audit.js）
- Step 06: 执行全部5项LLM分析检测 + **角色声音深度检测**（voice-check.js）
- Step 07-08: 修复循环上限2轮
- Step 08.5-08.6: 百分制评分+评分修复（上限3轮）
- 上下文读取：全量读取所有设定文件

#### batch模式（批量写作）
- 一次会话写2-3章（4000-9000字）
- 自适应批量计算：根据历史字数、剩余章数、角色复杂度动态调整
- 每章独立执行Phase 1-7
- 章节间自动传递上下文
- 完成后统一更新追踪文件

#### revise模式（修改/重写）
- 支持按章节名搜索定位
- 加载前后章上下文（前一章+后一章）
- **备份原文**：修改前复制为`正文/第{X}章_章名_原稿_{YYYYMMDD}.md`
- 确认修改范围：全文重写/局部修改
- **级联检查**：修改后检查伏笔变化、时间线变化、后续章节受影响项
- 字数对比：修改后与原文字数差异>30%或>800字时提醒

## 前置检查

新会话开始时，必须先读取：
1. `追踪/上下文.md` — 上次进度

## 核心流程（11步）

```
Phase 1: 准备（2步）
  Step 01: 目录健全检查 + 细纲验证
  Step 02: 细纲分析 + 对标处理 + 设定决策

Phase 2: 上下文注入（1步）
  Step 03: 读取上下文 + 约束生成

Phase 3: 写作（1步）
  Step 04: 正文写作

Phase 4: 检测（2步）
  Step 05: 脚本检测（BLOCK+WARN）
  Step 06: LLM分析检测（BLOCK+WARN）

Phase 5: 修复（条件，2步）
  Step 07: 综合修复
  Step 08: 复查

Phase 6: 评分（条件，2步）
  Step 08.5: 百分制评分
  Step 08.6: 评分修复（score<90时）

Phase 7: 收尾（1步）
  Step 09: 追踪更新 + 设定回写验证
```

## 详细步骤

### Step 01: 目录健全检查 + 细纲验证

**子agent类型**：general
**隔离执行**：是（context=none）

**任务**：
1. 检查项目目录结构是否完整
2. 检查细纲是否存在
3. 如果细纲不存在，创建细纲

**输出**：
- 目录状态报告
- 细纲是否存在
- 如果需要创建细纲，调用细纲生成流程

**验证**：
- [ ] 所有必要目录存在
- [ ] 细纲存在且格式正确
- [ ] 上一章正文存在（续写时）

---

### Step 02: 细纲分析 + 对标处理 + 设定决策

**子agent类型**：general
**隔离执行**：是（context=none）

**任务**：
1. 读取细纲，分析本章涉及的内容
2. 处理对标文件（如有）
3. 确定需要读取哪些设定文件
4. 确定是否需要创建新设定

**分析内容**：
- 本章涉及哪些角色
- 本章涉及哪些场景
- 本章涉及哪些势力
- 本章需要哪些设定支持
- 本章对标哪些作品/章节

**对标文件处理**（条件执行）：
如果项目有对标文件（对标书/对标章节），执行以下操作：
1. 读取对标文件，提取对标作品的写法特点
2. 分析对标作品的情绪曲线、节奏、爽点设计
3. 提取可借鉴的技法，融入本章写作约束
4. 输出对标分析报告

**设定决策**：
- 如果新角色出现 → 创建角色设定
- 如果新场景出现 → 创建场景设定
- 如果新势力出现 → 创建势力设定
- 如果已有设定 → 读取并验证

**文风召回**（条件执行）：
如果项目有对标文风.md，执行以下操作：
1. 读取对标文风.md，提取文风锚点
2. 分析对标作品的句式特点、用词风格
3. 提取可借鉴的文笔技法
4. 输出文风锚点摘要（<200字）

**输出**：
- 涉及角色列表
- 涉及场景列表
- 需要读取的设定文件列表
- 设定决策结果
- 对标分析报告（如有）
- 文风锚点摘要（如有）

**验证**：
- [ ] 涉及角色都有设定文件
- [ ] 涉及场景都有设定文件
- [ ] 设定决策已记录
- [ ] 对标分析已完成（如有对标文件）
- [ ] 文风锚点已提取（如有对标文风.md）

---

### Step 03: 读取上下文 + 约束生成

**子agent类型**：general
**隔离执行**：是（context=none）

**任务**：
1. 读取必要的上下文文件
2. 生成写作约束参数
3. 注入硬约束、文风约束、情绪约束

**分层读取策略**：

Layer 1 - 必读（<200字）：
- 追踪/上下文.md 索引块
- 细纲

Layer 2 - 按需（细纲涉及才读）：
- 设定/角色/{涉及角色}.md（2-3个）
- 设定/世界观/{涉及场景}.md（1-2个）
- 追踪/角色状态.md（只读涉及角色行）
- 追踪/伏笔.md（只读涉及伏笔行）

Layer 3 - 条件读：
- 跨卷追踪/跨卷伏笔.md（细纲标注跨卷伏笔时）
- 故事线/故事线_主线_*.md（细纲标注故事线推进时）

**约束生成**：
- 读取 `prompts/system-prompt.md` → 硬约束
- 读取 `prompts/genre-style.md` → 题材文风约束
- 读取 `prompts/emotion-guide.md` → 情绪约束
- 读取 `skills/_shared/references/quality-rules.md` → 质量约束

**追踪数据注入**：
```xml
<consistency_context>
  <pending_foreshadowing>
    - 伏笔1：...（埋设章节：第X章，待回收章节：第Y章，紧迫度：高/中/低）
    - 伏笔2：...（埋设章节：第X章，待回收章节：第Y章，紧迫度：高/中/低）
  </pending_foreshadowing>
  <character_states>
    - 主角：身份=...，能力=...，伤势=...，关系=...（一句话状态）
    - 女主：身份=...，能力=...，伤势=...，关系=...（一句话状态）
    - 关键配角：身份=...，状态=...（一句话状态）
  </character_states>
  <timeline>
    - Ch{N-2}：事件摘要
    - Ch{N-1}：事件摘要
    - Ch{N}（本章）：细纲目标
  </timeline>
  <items>
    - 物品1：位置=...，状态=...，重要度=高/中/低
    - 物品2：位置=...，状态=...，重要度=高/中/低
  </items>
  <environment>
    - 季节：...
    - 天气：...
    - 位置：...
    - 时间：...
  </environment>
</consistency_context>
```

**输出**：
- 上下文摘要（<1000字）
- 约束参数JSON
- 追踪数据摘要

**验证**：
- [ ] 上下文摘要包含必要信息
- [ ] 约束参数完整
- [ ] 追踪数据已注入

---

### Step 04: 正文写作

**子agent类型**：general
**隔离执行**：是（context=none）

**任务**：
根据细纲、上下文、约束参数，生成章节正文。

**写作指令**：
1. 读取细纲，明确本章要写什么
2. 读取上下文，明确前文状态
3. 读取约束，明确必须遵守的规则
4. 开始写作，遵循以下规则：

**写作规则**：
1. **直接输出正文**：不要添加标题、章节号或额外说明
2. **承接上文**：从上一章结尾状态直接向前推进
3. **遵循设定**：角色行为必须符合设定
4. **遵循文笔约束**：去AI味、五感描写、镜头式写作
5. **遵循情绪约束**：按照细纲标注的情绪弧线写作
6. **遵循一致性约束**：与前文情节、角色状态保持一致

**输出**：
- 章节正文（3000-4000字）

**验证**：
- [ ] 正文承接上文
- [ ] 角色行为符合设定
- [ ] 情绪有起伏
- [ ] 无明显AI腔

---

### Step 05: 脚本检测（BLOCK+WARN）

**子agent类型**：general
**隔离执行**：是（context=none）

**任务**：
运行自动化脚本检测，检查章节质量。

**检测项目**：

| 检测项 | 严重度 | 脚本 | 通过标准 |
|--------|--------|------|---------|
| 字数达标 | BLOCK | wordcount.js | ≥目标字数90% |
| 禁用词+AI腔 | BLOCK | style-lint.js | 0个一级禁用词 |
| AI标点符号 | BLOCK | punctuation-normalize.js | 0个AI标点 |
| 一致性 | BLOCK | consistency-check.js | 0个BLOCK项 |
| 跨章节检查 | WARN | cross-chapter-check.js | 0个重复段落 |

**检测命令**：
```bash
node skills/_shared/scripts/quality-gate.js 正文/第XXX章.md 项目目录
```

**输出**：
- 检测报告JSON
- 退出码（0=通过，1=WARN，2=BLOCK）

**验证**：
- [ ] 所有检测项已执行
- [ ] 检测报告格式正确
- [ ] 退出码正确

---

### Step 06: LLM分析检测（BLOCK+WARN）

**子agent类型**：general
**隔离执行**：是（context=none）

**任务**：
使用LLM进行深度分析检测。

**检测项目**：

| 检测项 | 严重度 | 说明 |
|--------|--------|------|
| 设定校验 | BLOCK | 比对细纲涉及的设定文件 |
| 章内逻辑性 | WARN | 情节是否合理、因果是否通顺 |
| 跨卷一致性 | WARN | 与前文情节是否矛盾 |
| 物品/角色/环境一致性 | BLOCK | 与追踪文件是否一致 |
| 角色声音一致性 | WARN | 角色对话是否符合性格锚点 |

**检测方法**：
1. 读取章节正文
2. 读取相关设定文件
3. 读取追踪文件
4. 使用LLM进行比对分析
5. 输出检测报告

**输出**：
- LLM分析报告
- 问题列表（按严重度排序）

**验证**：
- [ ] 所有检测项已执行
- [ ] 问题列表完整
- [ ] 严重度标注正确

---

### Step 07: 综合修复

**子agent类型**：general
**隔离执行**：是（context=none）
**条件触发**：Step 05或Step 06有问题时

**任务**：
根据检测报告，修复所有问题。

**修复规则**：
1. **BLOCK项必须修复**：不修复不能继续
2. **WARN项必须修复**：有问题就修复
3. **修复顺序**：先修复BLOCK，再修复WARN
4. **修复原则**：最小改动，不破坏原有内容

**修复流程**：
1. 读取检测报告
2. 按严重度排序问题
3. 逐个修复问题
4. 记录修复内容

**输出**：
- 修复后的章节正文
- 修复日志

**验证**：
- [ ] 所有BLOCK项已修复
- [ ] 所有WARN项已修复
- [ ] 修复日志完整

---

### Step 08: 复查

**子agent类型**：general
**隔离执行**：是（context=none）
**条件触发**：Step 07执行了才执行

**任务**：
修复后重新检测，确认问题已解决。

**复查规则**：
1. 重新运行Step 05和Step 06的所有检测
2. 确认所有BLOCK项已修复
3. 确认所有WARN项已修复
4. 如果仍有问题，返回Step 07修复（上限2轮）

**修复循环**：
```
检测 → 有问题 → 修复 → 复查 → 仍有问题 → 再修复（上限2轮） → 通过 → 下一步
```

**输出**：
- 复查报告
- 最终检测结果

**验证**：
- [ ] 所有BLOCK项已通过
- [ ] 所有WARN项已通过
- [ ] 修复轮次≤2

---

### Step 08.5: 百分制评分（条件执行）

**子agent类型**：general
**隔离执行**：是（context=none）
**条件触发**：Step 08复查通过后执行

**任务**：
运行百分制评分，评估章节整体质量。

**评分流程**：
1. 读取章节正文
2. 读取题材评分模板（`skills/_shared/score-templates/{题材}.json`）
3. 使用LLM进行15维度评分
4. 输出评分报告

**评分维度**（15个）：
| 维度 | 满分 | 评判重点 |
|------|------|---------|
| 开场吸引力 | 8 | 悬念钩子、冲突引入 |
| 情感深度 | 8 | 内心变化、共鸣代入 |
| 叙述结构 | 8 | 层次递进、结构紧凑 |
| 语言生动性 | 7 | 视觉语言、通俗易懂 |
| 细节描写 | 7 | 画面感、具体生动 |
| 过渡连贯 | 6 | 自然过渡、节奏紧凑 |
| 逻辑清晰 | 7 | 观点有力、因果合理 |
| 对比反差 | 6 | 主题突出、情感冲突 |
| 情感张力 | 7 | 张力吸引、高潮引导 |
| 人性化亲和 | 6 | 贴近生活、引发共鸣 |
| 视觉感官 | 7 | 视觉化、多感官 |
| 节奏流畅 | 7 | 紧凑不拖、速度控制 |
| 逻辑连贯 | 6 | 情节连贯、时间线清晰 |
| 细节具体化 | 5 | 具体例子、推动情节 |
| 情感爆发力 | 5 | 积累自然、爆发有力 |

**评分标准**：
- 总分 ≥ 90分：通过
- 总分 < 90分：需要修复

**输出**：
- 评分报告（各维度得分 + 总分）
- 低分维度列表（score < 满分60%的维度）

**验证**：
- [ ] 15个维度全部评分
- [ ] 总分计算正确
- [ ] 低分维度已标注

---

### Step 08.6: 评分修复（条件执行）

**子agent类型**：general
**隔离执行**：是（context=none）
**条件触发**：Step 08.5评分 < 90分时执行

**任务**：
针对低分维度进行定向修复。

**修复流程**：
1. 读取评分报告，定位低分维度
2. 针对低分维度生成修复指令
3. 执行定向修复（仅改低分维度涉及的内容）
4. 重新评分

**修复规则**：
- 每次只修复1-2个低分维度
- 修复后重新评分
- 最多3轮修复
- 3轮后仍 < 90分 → 阻断，输出最终评分报告

**输出**：
- 修复后的章节正文
- 修复日志
- 重新评分结果

**验证**：
- [ ] 低分维度已修复
- [ ] 重新评分 ≥ 90分
- [ ] 修复轮次 ≤ 3

---

### Step 09: 追踪更新 + 设定回写验证

**子agent类型**：general
**隔离执行**：是（context=none）

**任务**：
1. 更新追踪文件
2. 回写设定文件
3. 验证一致性

**追踪更新（按顺序）**：
1. 更新 `追踪/伏笔.md` — 新增/回收伏笔
2. 更新 `追踪/时间线.md` — 记录事件时序
3. 更新 `追踪/角色状态.md` — 更新角色状态
4. 更新 `追踪/物品.md` — 物品位置/状态变化
5. 更新 `追踪/环境.md` — 季节/天气/场景
6. 更新 `追踪/上下文.md` — 进度摘要

**设定回写验证**：
1. 检查设定文件是否需要更新
2. 如果有新设定，创建设定文件
3. 验证设定文件与追踪文件一致性

**输出**：
- 更新后的追踪文件
- 更新后的设定文件
- 一致性验证报告

**验证**：
- [ ] 所有追踪文件已更新
- [ ] 设定文件已回写
- [ ] 一致性验证通过

## 质量门禁

### 退出码说明
| 退出码 | 含义 | 触发条件 |
|--------|------|----------|
| 0 | pass | 全部检查通过 |
| 1 | warn | 有警告但无阻断 |
| 2 | blocked | 有阻断项（必须修复） |

### 门禁规则
- 退出码 2 时**不得标记任务完成**，必须修复后重新运行
- 退出码 0 或 1 时可以继续下一步

## 防偷懒速查清单

### 5条铁律（不可违反）

1. **必须读文件**：写正文前必须用Read工具读细纲，不得凭记忆写
2. **必须写文件**：追踪文件必须实际写入，不得只输出文本
3. **必须验证**：每步完成后必须验证输出文件存在且格式正确
4. **必须展示**：检测结果必须展示给用户，不得静默跳过
5. **有问题必修**：BLOCK项必须修复，WARN项必须修复，不得跳过

### 各步骤防偷懒要点

| 步骤 | 偷懒做法 | 正确做法 | 验证方法 |
|------|---------|---------|---------|
| Step 01 | 跳过目录检查 | 实际检查每个目录 | ls验证 |
| Step 02 | 不读细纲 | 必须Read细纲文件 | 检查输出是否包含细纲内容 |
| Step 03 | 不注入追踪数据 | 必须读取追踪文件并注入 | 检查输出是否包含追踪摘要 |
| Step 04 | 凭记忆写 | 必须读细纲+上下文后写 | 检查正文是否承接上文 |
| Step 05 | 跳过检测 | 必须运行quality-gate.js | 检查检测报告是否存在 |
| Step 06 | 不做LLM分析 | 必须逐项分析 | 检查分析报告是否完整 |
| Step 07 | 不修复WARN | WARN也必须修复 | 检查修复日志 |
| Step 08 | 不复查 | 必须重新检测 | 检查复查报告 |
| Step 09 | 不更新追踪 | 必须更新6个追踪文件 | 检查文件修改时间 |

## Agent契约

### 子agent隔离执行规则

1. 所有子agent使用 `context: "none"` 隔离执行
2. 中间结果存放在 `.workflow/` 目录
3. 每步输出JSON文件供下一步读取
4. 子agent不能直接修改项目文件，只能输出到`.workflow/`

### 输入输出契约

| 步骤 | 输入 | 输出 | 验证 |
|------|------|------|------|
| Step 01 | 项目目录 | .workflow/step01-report.json | 文件存在 |
| Step 02 | 细纲+项目目录 | .workflow/step02-analysis.json | 包含角色/场景/设定列表 |
| Step 03 | 上下文+约束 | .workflow/step03-context.json | 包含追踪数据摘要 |
| Step 04 | 上下文+约束 | 正文/第{X}章.md | 文件存在、字数>0 |
| Step 05 | 正文 | .workflow/step05-report.json | 包含退出码 |
| Step 06 | 正文+设定+追踪 | .workflow/step06-report.json | 包含问题列表 |
| Step 07 | 检测报告+正文 | 正文（更新后） | 问题已修复 |
| Step 08 | 正文 | .workflow/step08-report.json | 所有项通过 |
| Step 09 | 正文+追踪 | 追踪文件（更新后） | 文件修改时间更新 |

### 输出文件清单

```
.workflow/
├── step01-report.json        # 目录检查报告
├── step02-analysis.json      # 细纲分析报告
├── step03-context.json       # 上下文摘要+约束参数
├── step05-report.json        # 脚本检测报告
├── step06-report.json        # LLM分析报告
├── step07-fix-log.json       # 修复日志
├── step08-report.json        # 复查报告
└── step09-update-log.json    # 追踪更新日志
```

## 设定校验5维度

### Step 06 设定校验详细内容

| 维度 | 检查内容 | 常见问题 |
|------|---------|---------|
| 世界观规则 | 时代背景、社会规则、技术设定是否一致 | 穿越后还在用手机、古代出现现代物品 |
| 金手指规则 | 系统机制、能力限制、触发条件是否一致 | 系统突然多出新功能、能力无故增强 |
| 文风设定 | 语言风格、叙事视角、节奏是否一致 | 第一人称突然变第三人称、风格突变 |
| 题材核心梗 | 爽点模式、情绪目标、卖点是否一致 | 打脸文变成圣母文、爽点缺失 |
| 角色关系 | 亲疏、敌友、势力归属是否一致 | 敌人突然变朋友、关系混乱 |

## 逻辑检查5维度

### Step 06 章内逻辑性检查详细内容

| 维度 | 检查内容 | 常见问题 |
|------|---------|---------|
| 时间逻辑 | 事件发生顺序是否合理 | 一天内做太多事、时间跳跃无说明 |
| 因果逻辑 | 事件因果关系是否成立 | 没有铺垫突然爆发、结果无原因 |
| 角色逻辑 | 角色行为是否符合性格和动机 | 性格突变、行为无动机 |
| 空间逻辑 | 角色位置移动是否合理 | 瞬间转移、位置矛盾 |
| 动机逻辑 | 角色决策是否有合理动机 | 无理由帮助敌人、突然黑化 |

## 修复策略详细表格

### Step 07 修复策略

| 问题类型 | 严重度 | 修复方式 |
|---------|--------|---------|
| 字数不足 | BLOCK | 增加细节描写、对话、心理活动、环境描写 |
| 禁用词 | BLOCK | 替换为推荐表达（参考banned-words.md） |
| AI腔句式 | BLOCK | 改写为自然句式（参考anti-ai-writing.md） |
| 一致性错误 | BLOCK | 修正矛盾描述，对照追踪文件 |
| 设定违反 | BLOCK | 修正为符合设定的描述 |
| 逻辑问题 | WARN | 补充铺垫或调整情节，确保因果成立 |
| 跨章重复 | WARN | 改写重复段落，增加变化 |
| 角色声音不一致 | WARN | 调整对话为符合性格锚点 |
| 情绪平坦 | WARN | 增加情绪起伏，插入爽点或低谷 |
| 节奏问题 | WARN | 调整段落长短、句子节奏 |

## Task 跟踪集成

### 任务树模板

```
T-WRITE-{N}
├── T-PREP-{N}（准备）
│   ├── T-PREP-01: 目录检查
│   ├── T-PREP-02: 细纲分析+对标处理
│   └── T-PREP-03: 设定决策+文风召回
├── T-CTX-{N}（上下文注入）
├── T-DRAFT-{N}（写作）
├── T-CHECK-{N}（检测）
│   ├── T-CHECK-01: 脚本检测
│   └── T-CHECK-02: LLM分析
├── T-FIX-{N}（修复，条件）
├── T-SCORE-{N}（评分，条件）
│   ├── T-SCORE-01: 百分制评分
│   └── T-SCORE-02: 评分修复（score<90时）
└── T-TRACK-{N}（收尾）
```

### 条件创建规则
- Step 07（修复）：仅当Step 05或Step 06有问题时创建
- Step 08（复查）：仅当Step 07执行了才创建
- Step 08.5（百分制评分）：仅当Step 08复查通过后创建
- Step 08.6（评分修复）：仅当Step 08.5评分<90分时创建

### 循环处理规则
- 修复循环上限2轮
- 评分修复上限3轮
- 同一问题连续2轮未解决 → 阻断，输出最终报告
