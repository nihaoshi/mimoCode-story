# 子智能体使用指南

## MiMo Code 子智能体（actor 工具）

MiMo Code 的 `actor` 工具可以动态 spawn 子智能体执行独立任务。**不需要预定义 agent 文件**，所有子智能体通过 actor 工具按需创建。

## 写作系统中的子智能体场景

### 1. 并行拆文

同时拆解多本对标书：

```
actor spawn → "拆解《XXX》黄金三章，输出到拆文库/"
actor spawn → "拆解《YYY》黄金三章，输出到拆文库/"
```

两个子智能体并行执行，互不干扰。

### 2. 多视角审稿

从不同角度并行审查同一批章节：

```
actor spawn → "从结构角度审查第15-20章，检查钩子/节奏/反转"
actor spawn → "从人物角度审查第15-20章，检查一致性/动机/弧线"
actor spawn → "从文笔角度审查第15-20章，检查AI味/对话/描写"
```

### 3. 资料研究

写作中遇到需要查证的外部事实时：

```
actor spawn → "研究明朝科举制度的细节，输出到参考资料/"
```

研究完成后再继续写作，不阻塞主会话。

### 4. 扫榜数据采集

多平台并行采集：

```
actor spawn → "运行起点榜单采集脚本"
actor spawn → "运行番茄榜单采集脚本"
```

## 子智能体 vs 主会话

| 场景 | 用子智能体 | 用主会话 |
|------|-----------|---------|
| 并行拆文 | ✅ 独立任务 | ❌ 串行太慢 |
| 多视角审稿 | ✅ 独立视角 | ❌ 串行太慢 |
| 写正文 | ❌ 依赖上下文 | ✅ 必须串行 |
| 更新追踪文件 | ❌ 依赖前一章 | ✅ 必须串行 |
| 资料研究 | ✅ 独立任务 | ⚠️ 可以但会阻塞 |

## 注意事项

1. **正文写作不能并行**：长篇章节依赖上一章正文和追踪文件，并发会导致上下文断裂
2. **子智能体不继承主会话上下文**：需要在 prompt 中提供所有必要信息
3. **子智能体结果需要验证**：返回后主会话应检查产出质量
4. **不需要 `.claude/agents/` 目录**：MiMo Code 不使用预定义 agent 文件

## 不需要自定义 Agent 文件

MiMo Code 的子智能体系统与 Claude Code 的 `.claude/agents/` 机制不同：

| 特性 | MiMo Code (actor) | Claude Code (.claude/agents/) |
|------|-------------------|------------------------------|
| 定义方式 | 运行时动态创建 | 预定义 .md 文件 |
| 灵活性 | 高（prompt 可变） | 低（固定定义） |
| 配置文件 | 不需要 | 需要 .claude/agents/ 目录 |
| 适用场景 | 一次性任务 | 可复用的 agent |

本项目不需要创建任何 agent 定义文件。所有子智能体通过 `actor spawn` 动态创建。
